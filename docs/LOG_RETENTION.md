# 日志保留与清理

系统管理员登录管理后台后，打开“审计管理 → 日志保留设置”，即可查看各类历史数据的保存期限，也可以手动清理记录。

## 自动清理

API 服务启动时会检查一次，之后每 24 小时检查一次。修改保留期限后，无须重启服务；下次自动清理时会使用新设置。需要立即删除旧数据时，可以使用同一页面的手动清理功能。

保存期限的单位为天，允许填写 0 至 3650。填写 **0 天** 表示该类别不自动删除。旧记录只有在早于指定期限时才会清理。例如，保存 30 天，会删除创建或结束时间早于 30 天前、且符合清理条件的记录。

| 日志类别 | 默认保存期限 | 自动清理依据 |
| --- | ---: | --- |
| 远程连接记录 | 永久保留 | 连接记录的创建时间 |
| 文件传输记录 | 永久保留 | 传输记录的创建时间 |
| 安全告警 | 永久保留 | 告警记录的创建时间 |
| 用户登录记录 | 永久保留 | 登录记录的创建时间 |
| 管理操作记录 | 永久保留 | 操作记录的创建时间 |
| 结束连接记录 | 永久保留 | 请求完成或失效后，记录的最后修改时间 |
| 设置修改历史 | 永久保留 | 修改设置的时间 |
| 个人推送成功记录 | 30 天 | 实际发送时间 |
| 个人推送失败记录 | 90 天 | 最后修改时间 |
| 管理员邮件发送成功记录 | 30 天 | 实际发送时间 |
| 管理员邮件发送失败记录 | 90 天 | 最后修改时间 |
| 个人推送事件处理失败记录 | 永久保留 | 最后修改时间 |
| 管理员邮件事件处理失败记录 | 永久保留 | 最后修改时间 |
| 服务器运行日志归档文件 | 30 天 | 日志归档时记录的时间 |

系统通过每批最多 500 条记录的方式删除数据库历史记录，避免一次删除过多记录。已经完成、失败或失效的历史记录可按上述规则清理。处于等待、重试、发送中等状态的任务会保留，尚未完成的结束连接请求也会保留。

此外，系统会定期清除过期的安全审计事件去重信息和失效的活动远程连接记录。这些属于服务运行所需的临时数据，按各自的固定有效期管理。

## 手动清理

在“手动清理历史记录”区域，可以选择某一类别，也可以选择全部类别。提供三种方式：

1. **按照已保存的保留期限**：按照上表的实际设置清理；保存期限为 0 天的类别会保留。
2. **删除早于指定天数的记录**：手动指定 1 至 3650 天，清理早于该期限的历史数据。
3. **删除所选类别的全部历史记录**：清理所选类别中所有符合删除条件的历史数据，不受保存期限限制。

点击“查看符合条件的记录”后，页面会显示各类别预计清理的数量。确认数量和范围后，点击“确认清理”，系统会再次要求确认。**已删除的记录无法恢复。** 建议需要保留记录时先导出或备份数据库。

手动清理会再次检查每条记录的状态和时间，避免删除在预览后重新进入工作状态的任务。结束连接记录仅删除已完成或已失效的请求；个人推送、邮件通知以及事件处理记录仅删除已结束的相应记录。

## 服务器运行日志文件

配置文件中的 `logger.path`（默认 `./runtime/log.txt`）决定运行日志保存位置。

开启文件日志后，日志文件会在日期变化时归档；如果单个文件超过 32 MiB，也会进行归档。归档文件与当前日志保存在同一目录，文件名称包含日期和时间，例如：

```text
runtime/log.txt
runtime/log.txt.20261112-080000-000
```

后台会按照归档文件的时间清理旧文件。清理时会保留正在写入的 `log.txt` 文件，保证服务可以继续记录运行情况；无需重启服务。若 `logger.path` 留空，服务只向标准输出写入日志，保存和删除这些输出内容应通过容器平台或系统日志服务配置。

## 管理接口

只有系统管理员可以使用清理接口。普通账户以及仅被授予部分管理权限的账户无法执行日志批量删除。

预览默认保存期限对应的记录：

```http
GET /api/admin/audit/cleanup/preview?kind=all&mode=retention
```

预览某一类别中早于 30 天的记录：

```http
GET /api/admin/audit/cleanup/preview?kind=login&mode=older&days=30
```

确认并执行清理：

```http
POST /api/admin/audit/cleanup
Content-Type: application/json

{
  "kind": "login",
  "mode": "older",
  "days": 30,
  "confirmation": "DELETE_LOGS"
}
```

`kind` 可以是 `all`，也可以选择 `connection`、`file`、`alarm`、`login`、`operation`、`disconnect`、`settings_history`、`push_sent`、`push_failed`、`notification_sent`、`notification_failed`、`push_outbox_failed`、`notification_outbox_failed` 或 `server_log`。

`mode` 可以是 `retention`、`older` 或 `all`。当 `mode` 为 `older` 时，需要传入 `days`。执行删除时必须传入 `confirmation` 字段。接口通过认证后才会执行数据库操作；清理操作本身也会写入管理操作记录。

获取或修改已保存期限：

```http
GET /api/admin/audit/retention
POST /api/admin/audit/retention
```

提交保存期限时，应传入后台页面显示的各个数字字段。所有数据库表都通过现有自动迁移机制增加所需字段，无须手动修改表结构。
