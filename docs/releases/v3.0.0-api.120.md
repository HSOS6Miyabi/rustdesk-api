# RustDesk API v3.0.0-api.120

发行日期：2026 年 11 月 13 日

## 事件订阅与个人 API 密钥

用户现在可以在 **账户 → 消息推送** 中生成专用于事件订阅的 API 密钥，并通过 `GET /api/events/v1/stream` 接收实时事件。客户端使用 `Authorization: Bearer` 请求头认证，可选择订阅特定事件，也可以接收全部事件。

每个账户最多建立五条 SSE 连接，服务器进程最多接受 2048 条。接口每 20 秒发送一次心跳。客户端断开连接后，服务器会清理对应的订阅记录；如果某条连接的待发送消息超过 64 条，服务器会关闭该连接。密钥可随时撤销，原有连接会定期重新检查认证状态。

远程连接建立沿用现有 `connection.started` 事件。设备上线、离线、连接结束和其他已支持的事件也可以通过 SSE 订阅。

## 自定义 HTTP JSON 推送

消息推送页面增加 **HTTP JSON** 渠道。用户填写 HTTPS 接收地址，并选择需要接收的事件。服务器会将结构化 JSON 直接发送到指定接口，可选填 Bearer 密钥供接收服务认证。

HTTP 推送沿用已有的数据库发送队列、失败重试、发送状态与手动重新发送功能。事件标识在重试期间保持一致，接收服务可以根据标识避免重复处理。

## 多实例部署与资源管理

使用多个 API 进程时，可以通过共享 Redis 服务交换 SSE 事件。实例使用有有效期限的订阅记录，并在正常退出时主动清理。

SSE 接口使用受限制的连接数量与消息缓冲区。事件发送不会因单个客户端读取缓慢而持续增加内存占用。
