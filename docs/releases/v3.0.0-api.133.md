# v3.0.0-api.133

## WebClient 视频性能

WebClient 现在会检查浏览器对 VP9、H.264、H.265、VP8 和 AV1 的解码支持情况，并通过 RustDesk 1.5.3 原有协议与远程设备协商视频格式。浏览器优先请求硬件解码；实际使用的解码设备由浏览器和操作系统决定。远程设备仍需支持对应格式的编码。

浏览器原生解码器收到视频后，WebClient 会将解码完成的 `VideoFrame` 直接交给 Flutter 图像导入队列显示。这样可以减少视频图像复制、WebGL 像素读取和像素翻转造成的开销。如果当前 Flutter 环境无法直接导入视频帧，程序会使用 RGBA 图像显示方式。

当原生解码器无法运行时，程序会尝试浏览器的软件解码方式；仍无法解码的格式会从视频能力声明中移除，并请求远程设备重新发送关键帧。VP9 还保留 OGV.js WebAssembly 解码方案，以兼容缺少 WebCodecs 的浏览器。

程序按正确顺序处理压缩视频帧，在显示端处理速度较慢时保留较新的已解码画面，并释放不再需要的图像资源。视频处理与远程键盘、鼠标及剪贴板功能继续分别运行。

## 性能信息

WebClient 的画面性能栏显示连接方式、视频格式、解码方式、实际显示帧率、解码等待时间与绘制耗时。将鼠标移到性能信息上，还可以查看接收帧率、完成解码的帧率、解码队列长度、跳过绘制的帧数及接收视频的数据速率。

硬件解码偏好不能保证一定由 GPU 解码视频。实际效果会随浏览器、显卡驱动、远程设备编码能力、网络情况和显示分辨率变化。

## 更新与检查

更新 API 后，刷新 WebClient 页面，重新建立远程连接即可使用新的解码协商方式。此次更新没有调整数据库结构。

JavaScript 连接组件的检查命令：

```bash
cd resources/web/js
npm ci
npm run build
node --test tests/*.test.cjs
```

Chromium 浏览器测试还会检查 WebCodecs 视频图像转换、WebClient 的性能显示与远程桌面页面布局。建议使用同一台远程设备、相同的分辨率和网络条件，对比更新前后的帧率与操作延迟。
