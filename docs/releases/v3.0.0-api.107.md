# RustDesk API v3.0.0-api.107

发行日期：2026 年 11 月 11 日  
数据库迁移版本：**290**

本次更新增加了统一的设置中心，并改善数据库、通知处理、后台任务和多实例部署的可靠性。

## 主要功能与改进

- **全局设置中心**：系统管理员在 `/_admin/` 的“系统管理 → 设置中心”查看各项配置的中文说明、实际运行值、来源、网页覆盖状态和重启要求。启用网页覆盖后，相应设置优先于环境变量。
- **敏感配置保护**：网页不会返回密码和密钥原文。修改启动设置时保留上一版配置；涉及数据库切换时，先检查目标数据库连接和已有数据。
- **通知事件恢复**：将无法处理的事件单独保留，允许后续事件继续执行。管理员可以查看失败原因并重新提交。多实例共享任务时检查事件认领状态。
- **数据库与性能**：优化委派管理员角色、通知渠道等批量查询；保留未启用高级功能时的按需查询方式；可选缩短多实例策略和通知订阅缓存的有效时间。
- **任务与服务停止**：完善客户端安装包长任务的活动时间更新、下载取消和异常恢复，改进缓存资源释放与 HTTP 服务正常关闭。
- **部署与文档**：更新普通服务器和 Docker 的安装方法，补齐配置参考、功能改动、上游同步及数据库备份恢复说明。

## 升级注意事项

从 `v3.0.0-api.106` 升级时，数据库迁移版本由 **288** 更新到 **290**。建议先备份数据库、`conf/config.yaml`、`data/settings-bootstrap.json`（如存在）以及 SMTP、TOTP、消息推送和 RustDesk Server 所用的密钥。

程序启动时会执行数据库迁移。完成后，可以通过设置中心查看实际生效的配置。网页中的全局设置修改需重新启动 API。

Docker 镜像：

```bash
docker pull ghcr.io/hsos6miyabi/rustdesk-api:v3.0.0-api.107
docker compose pull
docker compose up -d
```

使用 Docker Compose 时，保持 `/app/data` 的持久化挂载，并为容器预留至少 75 秒的正常停止时间。升级独立 API 不会自动更新 RustDesk Server 的组合镜像。

## 兼容性与测试

- 配套维护的 RustDesk Server：`v1.1.17-api.21`。涉及严格设备登记、连接许可和控制角色时，应核对双方的内部通信设置。
- 客户端安装包管理支持 RustDesk 官方 1.5.1 的 Windows、Linux 与 macOS 版本。
- 已使用 GitHub Actions 检查 Go、并发处理、Chromium 管理界面、SQLite/MySQL/PostgreSQL 迁移与恢复，以及 Linux AMD64、Linux ARM64 和 Windows AMD64 构建。
- 真实 SMTP 服务商、跨地区公网中继、不同系统上的实际远程控制和生产数据库恢复，应在部署环境中完成相应检查。
