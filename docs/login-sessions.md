# 登录会话与数据库升级

## 登录有效期

新安装的 RustDesk API 默认将登录会话保存 30 天。管理员可以在设置中心修改“登录有效期”（`app.token-expire`），例如 `720h` 表示 30 天。已有安装保留原来的配置值。

对于数据库保存的随机令牌，用户保持登录并正常访问 API 时，系统会在会话剩余时间不足有效期的三分之一时自动延长有效期。使用 JWT 签名的会话在签名令牌到期后需要重新登录。退出登录、管理员撤销会话、账户密码变更，以及到达有效期后都会使相关会话失效。

未配置 JWT 签名密钥时，系统使用安全随机数生成登录令牌。配置了 `jwt.key` 时，系统生成与 RustDesk Server 兼容的 JWT 签名令牌。登录状态均保存在数据库中的 `user_tokens` 表。重启 API 容器后，只要数据库及其数据仍然存在、相关签名密钥保持不变，有效会话就可以继续使用。管理控制台在同一浏览器的不同标签页之间保留登录状态。请使用 HTTPS 访问控制台，并妥善保护浏览器中的登录信息。

如果 RustDesk Server 启用了 `MUST_LOGIN=Y`，请在 API 和 `hbbs` 中设置相同的 `RUSTDESK_API_JWT_KEY`，并在重启容器时保留原值。新签名令牌的有效期由 `app.token-expire` 控制。服务端同时检查 JWT 有效期和数据库会话是否有效。

## Docker 部署

使用 SQLite 时，必须保留容器的 `/app/data` 目录。项目提供的 Docker Compose 文件已经将该目录挂载到宿主机。使用 PostgreSQL 或 MySQL 时，请确保数据库服务持久保存数据，并使 API 重启后继续连接同一个数据库。

升级版本后，API 在启动时检查数据库版本，以及现有表、字段和索引。发现缺少内容时会自动执行数据库迁移，保留原有账户、授权提供者和登录记录。迁移发生错误时，API 会报告错误并停止启动，方便管理员检查数据库权限和日志。
