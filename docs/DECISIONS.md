# 技术方案选择

本项目面向小型团队，优先提供完整功能和简便管理，同时保留必要的安全检查。

## 开发分支与发布

两个仓库在 `development/m1-device-management` 上进行配套开发。默认分支使用持续集成验证；Release 与发行镜像只允许明确确认里程碑后发布。

## 保留现有账户登录

第一阶段官方客户端设备命令使用已存在的 Bearer 登录令牌。独立的 API 管理令牌留在后续功能计划中。设备归属和修改权限由服务器检查。

## 可选严格设备登记

出于小型团队使用方便的考虑，严格设备登记默认关闭。开启后必须由 API 批准设备 ID、UUID 和公钥，`hbbs` 才接受设备登记。

## 服务端与 API 分离

继续将 API 管理和设备连接服务保持为两个独立程序。严格设备登记通过受保护的内部 HTTP 接口处理，以便支持普通安装及 Docker 部署。

## 兼容官方客户端

优先实现客户端公开代码实际请求的 `/api/devices/cli` 和 `/api/devices/deploy`，返回客户端已知的数据结构。现有 `/api/admin` 管理接口保持可用。

## 集中策略的优先顺序

按设备、用户、设备组的顺序确定客户端实际使用的策略。历史设备直接分配优先级最高。禁用的策略不会阻止查找下一级有效策略。

## 管理令牌与官方设备命令

为 `--assign` 和 `--deploy` 提供独立 API 令牌，支持指定权限、有效期和撤销。普通客户端其他 API 继续使用账户登录令牌，防止自动化令牌获得额外接口权限。

## 结束活动连接

采用官方客户端已支持的心跳 `conns` 和 `disconnect` 字段。管理员只能请求结束近期确实被客户端报告的活动会话。请求状态与客户端的后续心跳共同用于判断是否已经完成。

## 地址簿 CSV 与恢复

支持标准 UTF-8 CSV 批量导入与导出，保留用户已保存的远程连接密码和其他客户端设置。导入时先验证数据，验证成功后才修改数据库。单独删除地址簿设备条目时可恢复，删除整个分类时永久删除其中的设备信息。

## 团队邮件设置

为小型团队提供统一的 SMTP 设置页面，允许管理员发送测试邮件，并为密码恢复及成员邀请提供邮件发送能力。需要认证密码时使用数据库加密存储，使用独立环境变量提供加密密钥。

## 邮箱密码恢复及邀请

账号密码恢复使用有效期 15 分钟、只能使用一次的邮件链接。成员邀请使用指定用户组和 1 至 30 天有效期，注册完成后不能再次使用。管理员可在邀请接受前撤销邀请。

## 可选 TOTP 双重认证

小型团队所有账户默认维持现有登录方式。每个用户可自行开启 TOTP，并在绑定时保存 6 个一次性恢复码。官方客户端使用已有的 `email_check`、`tfa_check`、`secret` 字段处理登录验证，避免修改客户端。双重认证凭据和 SMTP 密码使用统一的持久化加密密钥。

## 邮箱登录验证

邮箱验证码默认关闭，允许小型团队选择使用。绑定时必须证明能够接收当前账户邮箱的邮件。开启后密码登录将多出邮箱验证码步骤，除非用户已经启用了 TOTP，此时优先使用身份验证器。SMTP 服务不能发送邮件时，应向用户提示发送失败。

## 多中继服务器优先选择

首先提供用户可维护的 IP 网络范围规则，适合小型团队的办公地点和地区网络。连接双方都匹配同一节点时优先级更高，其次考虑节点的数值优先级；没有适用规则时轮流使用可用节点。未来可增加 GeoLite2 地理位置数据库，根据公开 IP 地址自动识别地区。

## 使用 GeoLite2 Country CSV 作为可选地区数据库

为了保持普通服务器和 Docker 部署的独立性，GeoLite2 国家级数据库在 hbbs 本地读取。该功能不增加网络位置查询服务调用，也不要求默认安装下载地图数据。管理员仍可使用 CIDR 直接指定办公网络，GeoLite2 国家代码提供额外的自动选择能力。

数据库使用 MaxMind 官方 Country CSV 格式，由管理员自行下载和更新。未来可在保持接口不变的条件下增加 MMDB 文件读取。
